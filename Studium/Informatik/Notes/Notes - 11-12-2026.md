## Nachrichtenverarbeitung
### Nachrichten
- Eine Nachricht ist eine aus den Zeichen eines Alphabets gebildete Zeichenfolge.
- Ein Automat ($Q, \Sigma, \delta, Y, g, z_{s}, E$) besitzt ein Eingabealphabet.
- Wenn unsere Nachricht aus Zeichen von $\Sigma$ besteht, welche Nachrichten akzeptiert der Automat?
### Beispiel
- $\Sigma = \{0, 1\}$
- $Q = \{a, b\}; \quad q_{s} = a; \quad E = \{b\}$
- $\delta(a, 0) = a; \quad \delta(a, 1) = b$
- -> Jede Nachricht, die beliebig viele 0 hat und dann mit einer 1 endet.

## Fangzustand
- Ist der Automat im Endzustand, dann hat er eine Nachricht erfolgreich gelesen.
- Wie sollen Fehler signalisiert werden?
- *Alternative 1:* separater Zustand, analog Endzustand.
- *Alternative 2:* Zustand in dem der Automat gefangen bleibt.
=> *Ein Fangzustand $x$ ist ein Zustand aus $Q$, für den gilt: $\delta(x, \sigma) = x$, für alle $\sigma \in \Sigma$.*

## Akzeptierte Sprache
- Eine Sprache ist eine Teilmenge von $\Sigma^*$.
- Sei $A = (Q, \Sigma, \delta, q_{s}, F)$ ein Automat.
- Die akzeptierte Sprache des Automaten $A$ wird als $L(A)$ bezeichnet.
- $L(A) = \{m \in \Sigma^* | \delta_{|m|}(m) \in F\}$
## Bemerkungen
- Im Kontext von Sprachen wird von Worten gesprochen, nicht immer von Nachrichten.
- Entsprechend wird die Variable $w$ genutzt, statt $m$.
- $L(A)$ ist so zunächst nur für einen deterministischen, endlichen Automaten definiert.
	- Man kann die Definition für nichtdeterministische, endliche Automaten erweitern.
	- Auch für nichtendliche Automaten, sofern die Nachricht endlich ist.
- Wenn der Automat $A$ aus dem Kontext klar ist, dann statt $L(A)$ kurz $L$ geschrieben.
- Unterschiedliche Automaten können die gleiche Sprache akzeptieren.
## Anwendungen
- Automaten erkennen, ob ein Wort $w \in \Sigma^*$ zur Sprache $L$ des Automaten gehört.
- *Beispiele:*
	- Ein Automat kann die Schlüsselworte von Python (oder anderen Programmiersprachen) erkennen.
		- `def, while, if, etc.`
	- Automaten können auch erkennen, dass eine Zeichenfolge kein Schlüssel wort ist.
	- Erkennen, dass eine Mailadresse wohlgeformt ist.
	- Korrekt aufgebaute URL oder Telefonnummer.
	- Ist eine Zeichenfolge in einer anderen enthalten?
- Mit Hilfe eines Ausgabealphabets können Zeichenfolgen in andere übersetzt werden.
	- Telefonziffern in Tonhöhe.
	- Idee: Python in Byte-Code ("py" -> "pyc"); Byte-Code in Maschinencode.
## Frage
- Kann man zu jeder Sprache einen Automaten konstruieren?
- Antwort: Sei $\Sigma = \{a, b\}$, Erstellen Sie einen Automaten, der die Sprache a…ab…b erkennt, wobei die Folgen a…a und b…b gleich lang sein müssen.
# Komplexere Sprachen
- Endliche Automaten können nur "einfache" Sprachen erkennen.
	- -> reguläre Sprachen (regex).
- Für komplexere Sprachen benötigen wir einen beliebig großen Zwischenspeicher.
## Stapelspeicher
- Auch: Kellerspeicher, engl. Stack.
- Stapel kann leer sein.
- Operation `push` legt ein Element oben auf den Stapel.
- Operation `pop` nimmt das oberste Element vom Stapel.
	- Außer bei leerem Keller.
- Stapel kann beliebig hoch, d.h. beliebig viele Elemente enthalten.
## Kellerautomaten
- Erweiterung der endlichen Automaten um einen Kellerspeicher.
- Zustandsänderung nun durch Zustand, Eingabe und oberstes Kellerelement.
- Wenn Keller leer ist, wird spezielles Zeichen gesendet.

### Kellersprachen
- Alle Sprachen, die von endlichen Automaten erkannt werden.
- Einige mehr, zum Beispiel:
	- Sei $\Sigma = \{a, b\}$. Erstellen Sie einen Automaten, der die Sprache a..ab..b erkennt, wobei die Folgen a..a und b..b gleich lang sein müssen.
		- -> Idee: Für jedes a wird ein x im Keller gespeichert; sobald b erkannt wird, muss solange vom Keller gelesen werden, bis # erkannt wird.
## Frage
- Kann man zu jeder Sprache einen deterministischen Kellerautomaten konstruieren.
- Antwort:
	- Sei $\Sigma = \{a, b\}$. Erstellen Sie einen Automaten, der die Sprache $L = \{m_{0}, m_{1}, \dots m{n} \dots m_{1}, m_{0} \quad | \quad m_{i} \in \Sigma, \quad 0 \leq i \leq n\}$
	- (Sprache der Palindrome von $\Sigma \to$ allgemeiner: Verschachtelung).
- Problem ist die Beschränkung des Kellerspeichers auf push und pop.
	- Man müsste „beliebiger“ lesen und schreiben können.
	- Oder: nichtdeterministische Kellerautomaten, um alle Möglichkeiten auszuprobieren.
	    - Komplex: pro Wahlmöglichkeit einen eigenen Kellerspeicher.
	    - Lassen sich leider nicht in deterministische Kellerautomaten umwandeln.

## Simulation
- Die Konfiguration einer Turing-Maschine lässt sich als Zahl darstellen.
	- Zustände, aktueller Zustand, Bandinhalte und Position des Kopfes.
	- Analog den Stellen in einer Dezimalzahl.
- Jeder einzelne Zustandsübergang überführt eine Konfiguration in die nächste.
- Wenn man die Konfiguration auf dem Band einer anderen Turing-Maschine speichert, dann kann diese die ursprüngliche simulieren.
	- Jedes Verhalten der Original-Maschine wird nachvollzogen.
- D.h. es gibt eine Universelle Turing Maschine, die alle anderen Turing-Maschinen simulieren kann.

## Formale Sprachen
### Definition
Eine Teilmenge $L ⊆ \ \Sigma^*$ heißt *formale Sprache* über einem endlichen Alphabet $\Sigma$.
### Bemerkung
- $\Sigma^*$ bezeichnet man als Notation die sog. *Kleenesche Hülle* des Alphabets.
	- d.h. die Menge aller Wörter beliebiger Länge.
- Soll das leere Wort $\epsilon$ nicht enthalten sein: *transitive Hülle $\Sigma^+$*.
- $L$ ist bisher dadurch bestimmt, was ein Automat erkennen kann.
- Wie in natürlichen Sprachen kann man $L$ auch über eine Grammatik bestimmen.
### Grammatik
- Eine Grammatik $G$ besteht aus:
	- Einem endlichen Alphabet $\Sigma$ von Terminalsymbolen.
	- Einer endlichen Menge $V$ von Nichtterminalsymbolen mit $V ∩ \Sigma = ∅$.
	- Einem Startsymbol $S \in V$.
	- Einer endlichen Menge $P$ von Produktionen $u \to v$, mit:
		- $u ∈ (V ∪ Σ)^* V(V ∪ Σ)^*$
		- $v ∈ (V ∪ Σ)^*$
	- "u -> v" bedeutet: ersetze eine Wortfolge $u$ durch eine Wortfolge $v$.
