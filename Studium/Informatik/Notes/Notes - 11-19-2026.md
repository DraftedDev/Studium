# Datenstrukturen
## Elementare Datenstrukturen
### Skalare Daten
- "skalar" -> Angabe einer Zahl.
- Ein einzelner (Zahlen)-Wert, nicht weiter (konzeptionell) unterteilbar <-> atomar.
- Boolean Type: "falsch" = 0; "wahr" != 0.
- Meist als 1-16 Byte in CPU / Speicher abgelegt.
### Felder (Array)
- Ziel: Mehr als ein Exemplar einer Datenstruktur hintereinander im Speicher ablegen.
- Ein Feld ist eine Homogene zusammengesetzte Datenstruktur, deren Elemente über eine Position angesprochen werden.
- Die Elemente eines Feldes werden konsekutiv im Speicher abgelegt
- Nur kleine Felder können von der CPU als Ganzes verarbeitet werden (-> SIMD).
- Die Position ist meist eine ganze Zahl >= 0, selten >= 1.
### Verbundene (Records, Strukturen)
- Ziel: Unterschiedliche Datenstrukturen, unter einem Dach, zusammenfassen.
- Beispiel: Adresse = Land + Postleitzahl + Ort + Straße + Hausnummer.
- Beispiel: physikalische Größe = Skalar + Einheit.
- Zugriff auf Elemente meist mittels Namen, selben über Position (Tupel).
- Werden seltenst von der CPU als Ganzes verarbeitet.
### Referenzen (Zeiger)
- Ziel: Speicheradresse einer Struktur verarbeiten.
- Vermeidung von Kopien, Aufbau komplexerer Strukturen.
- Beispiel: Zwei Personen leben zusammen und ziehen zusammen um.
- Beispiel: Gemeinsamer Datenpool, aus dem ein Prozess liest und ein anderer hinschreibt.
- Operationen: Adresse einer Datenstruktur, Datenstruktur unter bestimmter Adresse.
## Speicherplatzzuweisung
### Anforderungen
- Funktion oder Sprachelement, um zur Laufzeit Speicher einer definierten Größe anzufordern.
- Speicher wird durch interne Mechanismen verwaltet.
- -> Speicher kann wieder zurückgegeben werden.
- `void* malloc(size_t size)`; `new`; `make`.
### Freigabe von Speicher
- Wenn das Programm Speicher nicht mehr benötigt, wird er freigegeben.
- Wiederverwendung von freiem Speicher.
- `void free(void* ptr).
## Sequentielle Datenstrukturen
### Lineare Listen
- Homogene Datenstruktur.
- Das erste Element hat keinen Vorgänger, alle anderen haben genau einen Vorgänger.
- Das letzte Element hat keinen Nachfolger, alle anderen haben genau einen Nachfolger.
- Jedes Element besitzt einen Zeiger auf seinen Nachfolger; der vom letzten Element zeigt auf "nichts".
- Die Liste ist ein Zeiger auf das erste Element.
- Alternative: Doppelt-Verlinkte-Liste.
- **Operationen:** Einfügen, Löschen, Suchen, Traversieren.
### Ringlisten
- Endliche Anzahl von Elementen.
- Jedes Element besitzt genau einen Nachfolger.
- Jedes Element besitzt genau einen Vorgänger.
- Einfach oder doppelt verkettet.
### Stapel (Stack)
- Häufiger Anwendungsfall: Aufgaben zurückstellen.
	- Daten bisheriger Aufgabe müssen zwischengespeichert werden.
- Auf zuletzt zurückgestellte Daten muss nach Beendigung der neuen Aufgaben zugegriffen werden.
- LIFO: Last In, First-Out.
- "Kellerspeicher".
- **Operationen:** `push`, `pop`, `empty`, `top`.
### Warteschlange (Queue)
- Anwendungsfall: Aufgaben einplanen.
- Auf zuerst eingeplante Daten muss nach Beendigung der aktuellen zugegriffen werden.
- FIFO: First-In, First-Out.
- **Operationen:** `enqueue`, `dequeue`, `empty`.

### Bäume
- Ein *Baum* ist eine nicht-leere Menge von Knoten & eine Menge von Kanten, die gewisse Bedingungen erfüllen.
- Ein *Knoten* ist ein Object, das eine Identität besitzt & dem weitere Informationen zugeordnet werden können.
- Eine *Kante* ist eine Verbindung zwischen zwei (unterschiedlichen) Knoten.
- Ein *Pfad* ist eine Folge von unterschiedlichen Knoten, die durch Kanten verbunden sind.
- Die *Wurzel* eines Baumes ist ein besonderer Knoten. Zwischen der Wurzel & jedem anderen Knoten des Baumes existiert genau ein Pfad.
- Ein *Blattknoten* ist ein Knoten ungleich der Wurzel, der mit genau einem anderen Knoten verbunden ist.
- Ein *innerer Knoten* ist ein Knoten, der kein Blattknoten ist.
- Die *Ebene* eines Knotens ist die Länge des Pfades zur Wurzel.
- Die *Pfadlänge* eines Baumes ist die Summe der Ebenen aller Knoten.
- Sei X die Ebene eines Knoten K ungleich der Wurzel:
	- Dann gibt es genau einen Knoten der Ebene X-1, der mit K verbunden ist. Dieser Knoten heißt *direkter Knoten von K* (auch: parent).
	- Knoten der Ebene X+1, die mit K verbunden sind, heißen *direkte Nachfolger von K* (auch: children).
	- Knoten der Ebene X, die den gleichen direkten Vorgänger wie K besitzen, heißen *Geschwisterknoten* von K.
	- Sei 0 < N <= X eine ganze Zahl. Jeder Knoten der Ebene X-N mit einem Pfad zum Knoten K heißt *Vorgänger von K*. Diese Menge enthält genau X Knoten.
	- Sei N > 0 eine ganze Zahl. Jeder Knoten der Ebene X+1 mit einem Pfad zum Knoten K heißt *Nachfolger von K*.
- Der *Verzweigungsfaktor eines Knoten* ist die Anzahl seiner direkten Nachfolger.
- Der *Verzeugungsfaktors eines Baumes* ist das Maximum der Verzweigungsfuaktoren seiner Knoten.
- Jeder Knoten ist Wurzel eines *Unterbaumes*, der aus ihm & seinen Nachfolgern besteht.
- Ein *Wald* ist eine disjunkte Menge von Bäumen.
- Ein *geordneter Baum* ist ein Baum, bei dem die Reihenfolge der direkten Nachfolger festgelegt ist.
- Ein *N-ärer Baum* ist ein geordneter Baum, bei dem jeder Knoten nur eine bestimmte maximale Anzahl N von direkten Nachfolgern haben darf.
#### Vorteile
- Schneller Zugriff auch bei großen Datenmengen.
- Beispiel: 1.000.000 Daten.
	- Liste: 500.000 Zugriffe (Mittelwert).
	- Feld, unsortiert: 500.000 Zugriffe (Mittelwert)
	- Baum, Verzweigungsfaktor (VF = 2): 30 Zugriffe
	- Feld, sortiert: 30 Zugriffe (-> Algorithmen).
	- VF = 10: 9 Zugriffe
	- VF = 100: 5 Zugriffe.
- Automatische Sortierung möglich.
- Unveränderbare Unterbäume können gemeinsam genutzt werden.
	- (wenn Baum nach Erstellung nicht mehr geändert werden kann -> immutabel)
#### Operationen
- Wert hinzufügen
	- ggf. Knoten aufteilen
- Wert löschen
	- ggf. Knoten zusammenfassen
- Alle Werte traversieren
	- In einer best. Reihenfolge besuchen
- Wert suchen
	- Werte sollten geordnet sein -> Vergleichsoperation
#### Binärbäume
- Geordneter, 2-ärer Baum.
- Hauptspeicherdatenstruktur.
- Vereint Vorteile von Feldern & Listen.
- Lässt sich gut rekursiv definieren & programmtechnisch behandeln.
	- Jeder Unterbaum eines binären Baums ist ein binärer Baum.
	- Einfach zu formulierende Wahl zwischen "linkem" & "rechtem" Unterbaum.
	- (-> Algorithmen)
- => *Ein binärer Baum ist entweder die Wurzel eines anderen binären Baumes oder ein äußerer Knoten.*
##### Traversieren von Binärbäumen
- Preorder: Erst die Wurzel, dann den vollständigen linkten Baum, dann den vollständigen rechten Baum.
- Inorder: Erst den vollständigen linken Baum, dann die Wurzel, dann den vollständigen rechten Baum.
- Postorder: Erst den vollständigen linken Baum, dann den vollständigen rechten Baum, dann die Wurzel.
- Pro Ebene.
### Probleme
- Bäume können zu Listen "degenerieren".
- Unausgeglichene, "schiefe" Bäume.
- N-äre Bäume im Hauptspeicher nur für kleine N.

## Abstrake Datenstrukturen
### Menge
- Sammlung von Werten, bei der es nicht auf die Reihenfolge ankommt & jeder Wert nur einmal vorkommt.
- Operationen:
	- Wert hinzufügen.
	- Anfrage, ob Wert in Menge enthalten ist.
	- Wert aus Menge entfernen.
	- Über alle Werte einer Menge iterieren.
	- Vereinigungs-, Durchschnitts-, Differenz-, symmetrische Differenz-, ..., Menge.
#### Realisierung
- Feld, Liste oder Baum, bei der jeder Wert nur einmal vorkommt.
- Feld, bei dem die Position des Wertes aus dem Wert selbst errechnet wird ("Hashing").
- Abbildung der Wertemenge auf Wahrheitswerte.
### Abbildung
- Aus Werten einer Ausgangsmenge möchte man eindeutig Werte einer „Bildmenge“ ermitteln.
- Beispiel: Verzeichnis bildet Namen auf konkrete Daten ab.
- Beispiel: math. Funktionen.
- Operationen:
    - Wert aus Ausgangs- einem Wert aus Bildmenge zuordnen (gleicher Ausgangswert überschreibt frühere Zuweisung).
    - Gibt es Zuweisung für einen best. Ausgangswert?
    - Bildmengenwert auf Basis eines Ausgangswert ermitteln.
    - Zuordnung löschen.
    - Menge aller Ausgangswerte ermitteln.
#### Realisierung
- Feld, Liste oder Baum von Paarwerten, bei denen das erste Element des Paars nicht doppelt vorkommen darf.
- Paar von Felder/Listen, wobei das erste Element als Menge genutzt wird.
- Funktion in einer Programmiersprache.
- Ein Feld ist die Abbildung von ganzen, positiven Zahlen auf Werte.
### Multi-Menge
- "Sammlung" von Werten, bei der es nicht auf die Reihenfolge ankommt & jeder Wert mehrmals vorkommen kann.
- Operationen:
	- Wert hinzufügen.
	- Abfrage, wie oft Wert in Menge enthalten.
	- Wert aus Menge entfernen.
	- Über Werte einer Menge Iterieren.
#### Realisierung
- Abbildung von Werten auf ganze, positive Zahlen.
- Feld oder Liste von Werten.
- Feld oder Liste von Paaren (Wert, Anzahl), wobei Wert nur einmal vorkommt.
- Baum von Paaren, wobei nur nach Wert gesucht wird.
### Relation
- Beliebige Beziehungen zwischen zwei oder mehr Werten aus unterschiedlichen Mengen.
- Allgemeiner als Abbildung; Grundlagen für SQL.
- Mathematisch eine Menge von Tupeln.
- Operationen:
	- Tupel hinzufügen, Tupel löschen (wie Menge).
	- (Teil-)Relation, bei der mind. ein Tupelelement einen bestimmten Wert besitzt -> Selektion.
	- Neue Relation, bei der mind. eine Tupelposition entfernt wurde -> Projektion.
	- Indirekte Beziehungen ermitteln.
#### Realisierung
- Menge von Tupeln.
- Feld oder Liste von Tupeln.
- Graphen.
### Graph
- Definition siehe "Graph".
- Operationen:
	- Knoten hinzufügen, abfragen, köschen.
	- Kanten hinzufügen, löschen.
	- Menge der Kanten eines Knoten.
	- Alle Knote aufzählen.
- Gewichteter Graph: Kanten enthalten selbst noch Daten.
#### Realisierung
- Menge von Kanten.
- Menge von Knoten & Kanten.
- Verknüpfte Tupel, verkettete Speicherung.
## Zusammengesetzte Datenstrukturen
### Summentypen
- Datenstrukturen, deren Anzahl sich aus der Summe der möglichen Einzelanzahlen zusammensetzt.
- Vereinigungsmenge der einzelnen Datenstrukturen.
- „Entweder … oder“.
### Aufzählungen (Werte)
- Die möglichen Werte werden explizit aufgezählt & bilden eine eigene Datenstruktur.
- Beispiel: Enums.
### Aufzählungen (Datenstrukturen)
- Anstelle der möglichen Werte werden die alternativen Datenstrukturen aufgezählt.
- Beispiel: Ein Baum ist entweder leer oder ein Verbund aus Wert, linktem & rechtem Knoten.
- Ist eine Verallgemeinerung der Aufzählung von Werten.
- Beispiel: Unions.
